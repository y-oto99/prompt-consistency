# 自然言語の指示を検査するケースと期待判定

期待判定は各ケースの原文と入力状況に対する評価基準です。すべての指示を守れる読みでは「両立」、同時に守れない読みでは「衝突」とします。どちらの読みも成り立つ場合は「解釈依存」です。ここで示す読みはケース作成者によるもので、複数の読み手が同じ判断をするかは評価していません。

## 指示の配置を変えたケースと業務プロンプト

末尾が `_short`、`_section`、`_full` のケースは、同じ指示の組を三つの配置で比較します。`*` はこの三つの末尾を指します。ケースIDと期待判定の対応は [expected.json](expected.json) にあります。

| ケース | 期待判定 | 根拠 |
| --- | --- | --- |
| `research_*`、`reference_cause` | 解釈依存 | 「なぜ」を原因の特定と読むと、資料に根拠のある原因がなく衝突する。原因が分からない理由の説明で足りるなら「解決率は上がりましたが、対象も変わったため改修の効果だけは分かりません」と答えられる。 |
| `returns_*` | 解釈依存 | 「結論」を無条件の可否と読むと、開封状態が不明なので断定禁止と衝突する。「未開封なら返品できます」を結論として認めるなら両立する。 |
| `quotation_*` | 衝突 | 未知の用語を禁じる範囲は「回答全体」。原文のまま引用すべき唯一の該当文にその用語が含まれる。 |
| `reference_examples` | 解釈依存 | 資料にない事実の主張を禁じる読みなら、仮の例と明示して説明できる。資料にない内容を一切禁じる読みでは、具体例を示す義務と衝突する。 |
| `reference_quotation`、`editorial_quotation` | 両立 | 平易な言葉を使う指示は説明本文に適用される。引用欄に原文を置けば、本文は平易に書ける。 |
| `commerce_condition` | 両立 | 条件が不明な場合の断定禁止が「ただし」で明示されている。「未開封なら返品できます。開封済みか教えてください」と答えられる。 |
| `commerce_tracking` | 解釈依存 | 注文固有のリンクまで「注文情報」に含める読みでは衝突する。この文中でリンクは案内先にあたり、注文情報に含まれないと読むなら両立する。どちらの読みでも、一般リンクで代用できるとは仮定しない。 |
| `commerce_general` | 両立 | 問いは営業時間なので、個別の注文情報を出さずに公式の一般案内だけで答えられる。 |
| `editorial_public` | 衝突 | 公開FAQでは、引用欄を含めて未公開の製品コードが禁止されている。唯一の該当文を原文のまま引用すると、そのコードが入る。 |
| `editorial_short` | 両立 | 短くする指示に字数の上限や例外を削る要件はなく、例外を残して短くできる。 |

## 施設案内のケース

料金・設備・受付を扱う施設案内のプロンプト1本に、6つの入力状況を設定しています。いずれも抽出指示の調整に使わないケースです。ケースIDと期待判定の対応は [holdout_expected.json](holdout_expected.json) にあります。

| ケース | 期待判定 | 根拠 |
| --- | --- | --- |
| `venue_fee_values` | 解釈依存 | 資料に記載された二つの金額から差額500円を計算できる。「資料にある金額だけ」を記載額そのものに限ると、差額を示す義務と衝突する。見込み額を禁じる読みなら差額を示せる。 |
| `venue_fee_missing` | 衝突 | 一方の料金が不明なので、根拠のある差額を出せない。見込み額の禁止と、差額を必ず示す指示が衝突する。 |
| `venue_fee_explicit` | 両立 | 資料に差額が記載されているため、そのまま答えられる。 |
| `venue_display` | 両立 | 表示名を尋ねる依頼には明示された例外がある。引用欄に表示名を置き、本文を平易に書ける。 |
| `venue_access` | 両立 | 移動時間や利用できる設備を推測せず、二つの入口を説明できる。 |
| `venue_hours` | 両立 | 来館はできないが、予約の受付時間は告知にある。開館と受付を分けて案内できる。 |
